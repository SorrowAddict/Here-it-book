# Domain Rules — Here-it-book

## 1. 도메인 개요

이 프로젝트의 핵심 도메인은 다음과 같습니다.

- 도서 검색
- 도서 상세 조회
- 서고 위치 표시
- 서고 LED 점등/소등

---

## 2. 도서 검색

검색어를 기준으로 도서를 검색합니다.  
검색 결과는 **pagination**을 지원해야 합니다.

검색 결과에는 다음 정보가 포함되어야 합니다.

- `title`
- `image`
- `author`
- `publisher`
- `pubdate`
- `isbn`
- `description`
- `total_cnt`
- `borrowed_cnt`
- `available`

### 검색 관련 규칙

- 검색 결과는 목록 화면에 필요한 **요약 정보**를 제공하는 역할을 가집니다.
- 검색 결과는 상세 조회 응답과 일부 공통 필드를 가지지만, **상세 응답과 동일한 책임을 갖지 않습니다**.
- 검색 결과는 페이지네이션과 정렬 상태에 따라 일관되게 갱신되어야 합니다.
- 빈 검색어 처리 방식은 현재 프로젝트의 기존 UX 패턴을 우선 따릅니다.

---

## 3. 도서 상세 조회

검색 결과에서 특정 도서를 클릭하면 상세 정보를 조회합니다.

상세 정보에는 다음 정보가 포함되어야 합니다.

- `title`
- `image`
- `author`
- `publisher`
- `pubdate`
- `isbn`
- `description`
- `total_cnt`
- `borrowed_cnt`
- `available`
- `section`
- `floor`
- `direction`
- `map_url`
- `created_at`
- `updated_at`

### 상세 조회 관련 규칙

- 상세 조회는 검색 결과보다 더 많은 정보를 포함합니다.
- 상세 조회에서만 서고 위치와 지도 관련 정보가 제공됩니다.
- 검색 목록용 타입과 상세 조회용 타입을 하나로 억지로 합치지 않습니다.

---

## 4. 서고 위치 규칙

상세 페이지에서는 다음 세 필드를 조합하여 위치를 표시합니다.

- `section`
- `floor`
- `direction`

화면 표시 형식:

- `section-floor-direction`

예:

- `P2-3-left`

### 위치 관련 규칙

- `section`, `floor`, `direction`은 **서버에서 개별 필드로 내려옵니다**.
- UI 표시 시에만 `section-floor-direction` 형식으로 조합합니다.
- `section-floor-direction`을 하나의 원본 API 필드처럼 취급하지 않습니다.
- `direction` 값은 명세 없이 임의 번역/변환하지 않습니다.
- 별도 팀 규칙이 없다면, 응답값을 기준으로 일관되게 표시합니다.

---

## 5. 수량 규칙

다음 수량 필드는 의미적으로 일관되어야 합니다.

- `total_cnt`
- `borrowed_cnt`
- `available`

### 규칙

- `total_cnt >= borrowed_cnt`
- `available >= 0`
- `available`는 의미상 `total_cnt - borrowed_cnt`와 일관되어야 합니다.
- 음수 수량은 허용하지 않습니다.
- 검색 응답과 상세 응답의 공통 수량 필드는 동일한 의미를 유지해야 합니다.

---

## 6. 출판일 규칙

- `pubdate`는 `YYYYMMDD` 형식 문자열입니다.
- UI에서 포맷팅할 수는 있지만, 원본 의미를 바꾸지 않습니다.
- 정렬 기준이 출간일일 때는 이 필드 의미를 기준으로 동작해야 합니다.

---

## 7. LED 점등/소등 규칙

상세 페이지에서 점등 버튼을 클릭하면 해당 ISBN의 서고 LED를 점등합니다.

LED는 다음 방식으로 소등될 수 있습니다.

- 사용자가 수동으로 소등 버튼을 눌러 OFF 요청
- 도서를 서고에서 꺼낸 것이 인식되어 자동 소등

### LED 관련 규칙

- 자동 소등은 **단순 UI 토글이 아니라 외부 인식 이벤트에 따른 상태 변화**입니다.
- 자동 소등 여부를 판단하기 위해 **명세에 없는 폴링 API / SSE / WebSocket API / 상태 조회 API를 임의로 만들지 않습니다**.
- 자동 소등 반영 방식이 필요하면 현재 프로젝트의 기존 패턴 또는 별도 명시된 명세를 우선 따릅니다.
- LED 동작은 최소한 다음 상태를 고려해야 합니다.
  - 점등 가능
  - 점등 요청 중
  - 점등 완료
  - 소등 요청 중
  - 소등 완료
  - 실패

---

## 8. UI 상태 규칙

다음 상태는 항상 고려합니다.

- 로딩 상태
- 에러 상태
- 빈 결과 상태
- 성공 상태

LED가 있는 상세 화면에서는 추가로 다음을 고려합니다.

- ON 가능 상태
- OFF 가능 상태
- 중복 요청 방지 상태

---

## 9. 금지 규칙

다음은 금지합니다.

- 검색 응답과 상세 응답 구조를 임의로 합치기
- `available`를 하드코딩된 값처럼 다루기
- `section`, `floor`, `direction`을 하나의 원본 응답 필드로 취급하기
- 자동 소등을 단순 UI 토글로 축약하기
- 명세에 없는 백엔드 동작을 추측으로 구현하기
